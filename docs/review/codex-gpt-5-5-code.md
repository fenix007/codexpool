### Топ-5 блокеров до первой сборки

В показанной части явных достоверных блокеров именно компиляции не видно: синтаксис `axum::serve` для axum 0.8 корректный, `todo!()` компилируется, `reqwest`/`rusqlite`/`aes-gcm` API здесь ещё не используются.

Но есть блокеры первого реального запуска:

1. `src/main.rs:36` — `data_dir` не создаётся до открытия SQLite.
2. `config.example.toml:5` + `src/main.rs:36` — example-config на чистой машине приведёт к ошибке открытия БД.
3. `src/main.rs:56-60` — возможная потеря внутренней ошибки `stats_writer`, если это `JoinHandle<Result<_>>`.
4. `src/config.rs:119-121` — небезопасная проверка loopback через `starts_with`.
5. `src/config.rs:21`, `111-115` — `ModelsConfig::default()` даёт пустой `default_scope`.

### Оценка: сколько правок до `cargo check` зелёного`

По этой части отдельно: примерно **0–3 правки**, если остальные модули имеют ожидаемые сигнатуры. Главный потенциальный compile-risk здесь — тип `stats_writer` в `try_join!` и feature/MSRV дрейф зависимостей без `Cargo.lock`.

По всему проекту оценить нельзя до частей 2–6.

### Топ-5 блокеров до первой сборки

В этой части явных безусловных блокеров компиляции не видно. Потенциальные блокеры зависят от сигнатур вне фрагмента:

1. `Pool::accounts_expiring_within` должен возвращать owned `AccountId`, не `DashMap` guards/refs, иначе `tokio::spawn` потребует `'static`.
2. `Upstream::auth_client()` должен возвращать owned `reqwest::Client` или другой `Send + 'static` тип.
3. `Pool::refresh_account(&id, &http)` должен принимать именно `&AccountId` и `&reqwest::Client`; иначе будет mismatch.
4. В `Cargo.toml` у `reqwest` должна быть включена feature `json`, иначе `Response::json()` не будет доступен.
5. В `Cargo.toml` у `chrono` должна быть включена поддержка `clock`/`now`, иначе `chrono::Utc::now()` может быть недоступен в зависимости от feature-набора.

### Топ-5 блокеров до первой сборки

1. `Ok(Some(Err(e))) | Ok(None)` — binding `e` не присутствует во всех альтернативах pattern.
2. `stream_with_accounting` возвращает пустой stream: успешные ответы становятся `200` с пустым телом.
3. `stream_with_accounting` не освобождает `inflight`: после первого успешного commit счётчики будут утекать.
4. `stream=false` фактически не поддержан: запрос переписывается в `stream=true`, а ответ маркируется как `application/json`.
5. Рекурсивный retry после `401` сбрасывает `refreshed_once`, возможен бесконечный refresh/retry loop и потеря stats-события.

### Топ-5 блокеров до первой сборки

В показанных двух файлах гарантированных compile-time блокеров не видно. Условные блокеры, зависящие от `Cargo.toml` и определений из других частей:

1. Отсутствие `chrono` feature `serde` для `DateTime<Utc>`.
2. Отсутствие `Serialize` у `pool::Scope`.
3. Несовпадение типов `StatsConfig.channel_capacity` с `usize`.
4. Несовпадение фактических сигнатур методов `Store` с вызовами `summary`, `timeseries`, `requests`, `insert_events` и остальных.
5. Несовпадение типов полей `pool::Pool::snapshot()` с использованием в `serde_json::json!`.

Guaranteed runtime blockers: `/stats/export`, `/stats/stream` и `/metrics` паникуют из-за `todo!`, но это не блокирует `cargo check`.
